# Lila docs profile

## Readers

Game artists and technical artists, most coming from Maya, some from Blender. They know 3D; they don't know Lila. Many read the page with Lila open next to it.

## Voice

- Document only what Lila's UI doesn't already show. A tooltip, option box label or Attribute Editor field already explains itself; the page covers what to do with it and what goes wrong.
- Planned features are described as done. Never mark a page as ahead of the build.
- Experimental features open with the experimental warning: subject to change, may lose data, feedback wanted.
- Menu paths in bold with ` > `: **Mesh > Clay > Create Clay**. Preferences the same way: **Preferences > General > Telemetry**.
- Python examples call commands bare, as typed in the script editor: `addAttr(...)`, not `ops.addAttr(...)` and no `from lila import ops`. Only code that runs as a module (an extension's Python, a standalone script file) imports `from lila import ops` and writes `ops.addAttr(...)`, and says so.
- Maya comparisons are welcome where they save a Maya user from guessing ("like Maya's Duplicate Special").

## Terms

- "3D app", never "DCC".
- Lila's add-ons are "extensions". "Plugin" only for Unreal, Qt or Maya plugins (LilaLink is an Unreal plugin).
- No generative AI features are described or implied; artist-assisting ML is fine.

## Structure

- Every page follows `docs/template.md`: one sentence on what it covers, Get it working, Troubleshooting, Options.
- A new page goes in `docs/_sidebar.md` and needs its icon in `docs/theme.css` (the `::before` selector list and an `--icon` line); the pre-commit hook rejects it otherwise.
- `docs/python/` and `docs/nodes/` are generated by `lila._apipages` and `lila._nodepages` in the Lila repo: fix their text in the command docs, docstrings or node declarations, then regenerate.

## Verify

`.docs/verify.py` checks `ops.*` and other `lila` calls against `python/lila` in the Lila checkout (`LILA_SRC`, default `../Lila`) plus commands registered in C++, and checks each part of a bold menu path appears as a string literal in the source. A miss is a candidate: confirm by finding the label or command (grep `label = "...` and `.name = "...` in `src/` and `extensions/`). Composed labels and option box sections can miss legitimately.

For anything the static check can't settle, a test instance answers it: set `LILA_CONFIG_DIR` to a scratch dir and `LILA_MCP_PORT` to a free port, start `build/` or `build-night` lila, query over MCP `execute_python`, kill only that PID. Never launch or kill Jared's own instance.
